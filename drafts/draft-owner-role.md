### 3.3 ה-ERD הלוגי (שינוי Schema, מסלול ב בלבד)

תרשים 07a, אנשים וגישה:

```
BUSINESSES  { BusinessID PK, businessName, isActive, createdAt }
OWNERS      { OwnerID PK, BusinessID FK, authUserID UK "שירות הזהות", fullName, email, isActive, createdAt }
COACHES     + BusinessID FK
COACH_INVITES { CoachInviteID PK, BusinessID FK, CoachID FK "רשות, עד ההצטרפות",
                inviteeName, inviteeEmail, token UK, status "open, accepted, expired", expiresAt, createdAt }
```

שלוש הכרעות פתוחות ב-ERD:

1. **SETTINGS**: היום לפי CoachID. האם המחירים והכללים הם של העסק (BusinessID), של המאמן, או של העסק עם אפשרות לחרוג?
2. **COACH_INVITES מול INVITES**: טבלה נפרדת (מוצע, כי INVITES היא נתון פרטי של trainees), או עמודת סוג ב-INVITES.
3. **מאמן עצמאי**: האם כל מאמן שייך לעסק, ולמאמן עצמאי יש עסק של אדם אחד שהוא גם בעליו (מוצע, כדי שלא יהיו שני מסלולים בקוד)?

המשמעות: migration חדשה שממלאת BusinessID לכל מאמן קיים. נתוני ההדגמה גדלים בבעל עסק אחד ובמאמן שני.
