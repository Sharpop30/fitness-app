# מדריך הגיבוי: fitness-app

| הסקריפט | scripts/backup.sh |

## מתי מגבים

1. **פעם בשבוע**, כל עוד הפיילוט רץ.
2. **לפני כל שינוי במבנה המסד בענן** (migration חדשה שעולה בפקודה db push). הסוכן יבקש גיבוי לפני השינוי, ולא יעלה אותו בלי גיבוי שנבדק.

## מה צריך לפני שמתחילים

1. **Docker Desktop פתוח**, והמסד המקומי פועל. בדיקת הגיבוי טוענת אותו למסד זמני במחשב. אם Docker סגור: לפתוח את Docker Desktop, לחכות שיעלה, ולהריץ `supabase start` מתיקיית הפרויקט.
2. **סיסמת ההצפנה**. היא אצל הצוות בלבד. לעולם לא בצ'אט, לא בקובץ ולא במאגר. בלעדיה אי אפשר לשחזר את הגיבוי, ולכן שומרים אותה במקום בטוח.

## שלושת הצעדים

**צעד 1: יוצרים את הגיבוי.** בטרמינל, מתיקיית הפרויקט, מדביקים פעם אחת:

```bash
scripts/backup.sh create ~/Documents/"גיבויים fitness-app"
```

הסקריפט קורא מהענן ואינו משנה בו דבר. הוא שואל פעמיים את סיסמת ההצפנה. בזמן ההקלדה לא מופיעים תווים, וזה תקין. בסוף מופיעה השורה `Backup:` עם שם הקובץ החדש, למשל `fitness-app-20261003-2258.tar.gz.enc`.

**צעד 2: בודקים את הגיבוי.** מחליפים את שם הקובץ בשם שהופיע בצעד 1:

```bash
scripts/backup.sh verify ~/Documents/"גיבויים fitness-app"/fitness-app-20261003-2258.tar.gz.enc
```

הסקריפט שואל את הסיסמה, טוען את הגיבוי למסד זמני במחשב, ומשווה את מספר השורות בכל טבלה למספר שנספר בענן. גיבוי תקין מסתיים בשורה:

`The backup loads, and the row counts match the cloud`

**צעד 3: מעלים עותק ל-Drive האישי.** את הקובץ מהתיקייה "גיבויים fitness-app" גוררים ל-Drive האישי. **לא ל-Drive המשותף**, ולא לתיקיית הפרויקט.

## איפה הגיבויים נמצאים

| המקום | מה |
| :-- | :-- |
| מסמכים, התיקייה "גיבויים fitness-app" | העותק הראשי. התיקייה פתוחה רק למשתמש במחשב. היא מסונכרנת גם ל-iCloud, והקובץ מוצפן |
| Drive האישי | העותק השני, שמועלה ידנית |
| לעולם לא | המאגר ב-GitHub (הוא ציבורי) או ה-Drive המשותף. בגיבוי יש נתונים אישיים של מתאמנים |

## מה יש בגיבוי

כל הנתונים של העסק בענן: המתאמנים, התוכניות, האימונים, התשלומים, ההגדרות ויומן הפעולות. בנוסף, משתמשי הזהות (המיילים והכניסות). מבנה הטבלאות עצמו אינו בגיבוי, כי הוא נבנה מה-migrations שבמאגר.

## כשמשהו נכשל

| מה רואים | מה עושים |
| :-- | :-- |
| `no such file or directory` | הטרמינל לא בתיקיית הפרויקט, או שהפקודה הודבקה פעמיים. עוברים לתיקיית הפרויקט ומדביקים פעם אחת |
| `The local stack is not running` | פותחים את Docker Desktop, מריצים `supabase start`, ומריצים שוב את צעד 2 |
| `bad decrypt` | הסיסמה שהוקלדה שגויה. מריצים שוב ומקלידים בזהירות |
| `different:` בטבלה של auth (sessions, refresh_tokens, audit_log_entries) | מישהו נכנס לאפליקציה בין הספירה להעתקה. מריצים שוב את צעד 1, ואחריו את צעד 2 |
| `different:` בכל טבלה אחרת | הגיבוי לא תקין. לא מעלים אותו ל-Drive, ולא מבצעים שינוי במסד בענן. מעתיקים לסוכן את מה שהודפס |
| כל שגיאה אחרת | מעתיקים לסוכן את מה שהודפס |

## שחזור

שחזור לענן הוא פעולת כתיבה על נתוני העסק, ולכן אינו מבוצע בלי הכרעה מפורשת של הצוות (CLAUDE.md, סעיף 6, "עבודה מול ייצור", כלל 4). אם יידרש, הסוכן יכין תוכנית שחזור לאישור, על בסיס הקובץ האחרון שעבר את צעד 2.
